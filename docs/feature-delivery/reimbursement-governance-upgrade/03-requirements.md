# 报销治理升级：需求草案

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| REQ-101 | Must | 管理员拥有注册审批页面，可按状态查看注册申请并直接批准或拒绝，不要求填写批准意见或拒绝原因；审批请求只接受必填 `concurrencyToken`，旧 `comment` 字段不再兼容；处理后立即刷新并保留状态、处理人和处理时间；普通申请人不能访问。 |
| REQ-102 | Must | 管理员可创建、编辑和停用项目；项目编码或名称具备明确唯一规则；有历史报销的项目不得物理删除。 |
| REQ-103 | Must | 新建差旅行程报销和普通单据报销时必须选择一个启用项目，服务端校验项目有效性，不能只依赖前端下拉框。 |
| REQ-104 | Must | 每笔报销稳定关联一个申请人和一个项目，支持按“项目 -> 人员 -> 报销”查询；修改项目也属于报销内容修改，必须生成新版本。 |
| REQ-105 | Must | 报销编辑页将“保存草稿”和“提交审核”分离；保存草稿不得自动提交，提交仍执行现有完整性校验。 |
| REQ-106 | Must | 当前报销在批准前允许申请人编辑或删除；删除采用作废/撤回，批准后禁止编辑和删除。 |
| REQ-107 | Must | 每次保存修改均生成新版本并作废旧版本；审批只能作用于当前已提交版本，任何旧版本审批请求必须失败且不得改变业务状态。 |
| REQ-108 | Must | 报销审批状态后增加独立发放状态；批准后为待发放，只有管理员可确认已发放，并记录操作者、时间和备注。 |
| REQ-109 | Must | 管理员拥有“全部报销”汇总页面，可按项目、用户、审批状态、发放状态和日期筛选，支持项目/用户分组、分页，并显示笔数和当前有效版本金额合计。 |
| REQ-110 | Must | “我的报销”显示项目和独立发放状态，支持按项目、审批状态筛选，并为允许操作的记录提供查看、编辑、删除/撤回按钮。 |
| REQ-111 | Must | 项目变更、报销版本切换、提交、撤回、批准、驳回和发放确认全部写入审计；旧版本及其审批记录可追溯但不可再次操作。 |
| REQ-112 | Must | 按用户授权执行破坏式数据库重建：清空现有业务数据库并按新模型重新迁移和初始化；不保留或迁移当前用户、报销、附件元数据和审批记录。对应私有附件对象必须同批次清理，不能留下无主文件。 |
| REQ-113 | Should | 注册审批、项目管理、审核工作台和全部报销均采用服务端分页与筛选，页面展示明确的空状态、加载状态和并发冲突提示。 |
| REQ-114 | Out of scope | 自动付款、财务系统实时同步、多级审批、预算控制、OCR 和发票验真。 |
| REQ-115 | Must | 业务角色简化为 `Applicant` 和 `Administrator`；管理员统一负责注册审批、项目管理、报销审批、发放确认和全量汇总，不设置或展示独立 `Reviewer` 角色。 |
| REQ-116 | Must | 正式移除 MinIO 依赖和运行服务；附件只写入可配置的本地私有目录，目录不可写时 API 启动失败并给出明确错误；Docker 使用持久化附件卷，备份恢复必须覆盖数据库与附件目录。 |
| REQ-117 | Must | 用户登录成功后在当前浏览器标签页刷新仍保持登录；主动退出、JWT 到期或鉴权接口返回 401 时立即清除本地会话；不使用长期 `localStorage` 保存 JWT。 |
| REQ-118 | Must | 用户上传的 JPG、PNG、PDF 凭证可在鉴权范围内在线预览并保留下载；新增报销时差旅行程默认生成“去程交通”和“回程交通”，普通单据只生成一个类别为空的“费用 1”，手动添加费用的类别也为空；“添加费用”按钮位于费用列表末尾；新增和编辑报销弹窗只保留一个纵向滚动区域。 |

## 默认业务规则

- 所有启用项目对全部申请人可选，不建立 `ProjectMember` 关系。
- 审批状态与发放状态不可互相替代；未批准报销的发放状态显示“无需发放”。
- 仅当前有效版本进入列表统计和金额汇总，历史版本不重复计入。
- 管理员待审批列表和审批入口只展示 `Submitted` 且当前版本未作废的记录；全部报销详情仍可追溯历史版本。
- 用户编辑已提交报销后，新版本回到草稿，必须重新点击“提交审核”。
- “删除”在页面使用用户习惯文案，服务端实现为可审计的 `Cancelled`。
- “已发放”是不可直接撤销的终态；首期不提供退回“待发放”的按钮或普通接口。
- 当前数据库和私有附件数据不纳入兼容迁移，实施时按确认目标执行破坏式重建。
- 管理员可以审批自己以申请人身份提交的报销，但必须保留完整审计记录。
- 停用项目不能用于新报销或被其他报销新选择；已经引用该项目的在途报销可以保留原项目继续流转。
- 汇总日期筛选首期按报销创建日期定义。
- 本地文件路径以配置根目录和数据库相对对象键组合，不接受逃逸根目录的对象键；附件继续通过鉴权 API 访问。
- `Unspecified` 只用于保存未选择费用类别的草稿；提交审核时前后端都必须拒绝该值。
- 在线预览继续复用鉴权下载接口，由前端创建临时 Blob URL；关闭预览或销毁组件时必须释放 URL，不开放附件静态目录。
