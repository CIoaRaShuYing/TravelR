# 报销治理升级：新增功能验收标准

## 餐补

| 需求 | 验收标准 | 验证方式 | 状态 |
| --- | --- | --- | --- |
| 自动同步申请 | 每次新建差旅报销自动生成一条餐补子记录；页面没有“是否申请餐补”开关；保存草稿和提交时两者同事务落库；普通单据报销不生成餐补；不能脱离差旅报销创建、撤回或删除餐补 | API 集成测试 + 浏览器流程 | confirmed |
| 餐补天数计算 | 同日往返显示 1 天；8 月 10 日至 8 月 12 日显示 3 天；返程早于出发日不可保存/提交；服务端不接受伪造天数；不读取时分 | API 集成测试 + 浏览器流程 | confirmed |
| 两次顺序审核 | 管理员先独立审核差旅，再独立审核餐补；差旅未通过时餐补控件禁用；差旅通过不会自动批准餐补，必须再输入日标准并确认；两次通过产生两条独立审批记录 | 状态机/事务测试 + 浏览器流程 | confirmed |
| 联动驳回 | 差旅驳回时餐补同事务自动驳回并带相同原因，不要求管理员再次点击驳回；联动失败时差旅驳回也必须回滚 | 状态机/事务测试 | confirmed |
| 金额确认 | 输入 100.00 元/日、3 天显示 300.00 元；空值、0、负数和非法精度不能审核；确认后保存唯一金额快照和审批记录 | 服务端测试 + 并发冲突测试 | confirmed |
| 两步发放 | 差旅报销和餐补分别审核、分别进入待发放、分别确认已发放；重复确认返回冲突；日志不含完整卡号 | 权限测试 + 审计检查 + 浏览器流程 | confirmed |
| 来源版本 | 差旅行程被修改并生成新版本时餐补随新版本重新保存；原报销费用总额不被餐补改变 | 版本切换集成测试 | confirmed |

## 月度导出

| 需求 | 验收标准 | 验证方式 | 状态 |
| --- | --- | --- | --- |
| 权限与条件 | 普通用户导出返回 403；管理员必须选择项目；停用项目可导出历史；日期区间可不选 | API 权限/参数测试 | confirmed |
| 默认区间 | 2026-08-10 未选择日期时默认 2026-07-10 至 2026-08-10；后端包含 7 月 10 日零点至 8 月 10 日全天的 `SubmittedAt` 记录 | 日期边界集成测试 + 浏览器默认值 | confirmed |
| 手工区间 | 选择 2026-08-01 至 2026-08-10 时包含起止两日全天，只按 `SubmittedAt` 筛选，不按费用、审核或发放日期 | 日期边界集成测试 | confirmed |
| 完整范围 | 多页数据导出的行数等于服务端完整查询；草稿排除；已提交、已批准、已驳回、已作废纳入；版本不重复 | 构造 25 条以上数据后断言文件 | confirmed |
| 文件内容 | `.zip` 根目录包含一份可正常打开的 `.xlsx` 和 `报销凭证/` 文件夹；Excel 至少有汇总、费用、行程工作表，餐补单独工作表/合计；无完整银行卡号和鉴权信息；无数据时仍有带表头 Excel 和空凭证文件夹 | ZIP 解压 + Excel 打开检查 + 敏感字段扫描 | verified |
| 汇总总计 | “报销汇总”最后一行显示“总计”、导出笔数和报销金额列合计；金额等于本次导出全部报销当前有效版本的 `TotalAmount` 之和，不包含餐补金额 | 构造多笔不同金额数据并校验工作表 XML/Excel 显示 | verified |
| 凭证范围 | 仅导出筛选结果中每张报销单当前有效版本关联的全部费用凭证，不导出草稿、旧版本或范围外报销的凭证 | 构造跨项目、跨日期、含旧版本数据后检查 ZIP 条目 | implemented |
| 凭证命名 | 文件名使用 `PersonalName_费用明细金额.原扩展名`，金额固定两位小数；非法字符替换为 `_`；重名时从第二个文件开始追加 `_2`、`_3`，不得覆盖或漏掉凭证 | 多用户、同名、同金额、多凭证 ZIP 条目断言 | verified |
| 缺失文件 | 数据库存在凭证记录但实体文件缺失或不可读时，接口返回明确失败，不返回部分成功的 ZIP | 删除隔离测试存储中的一个实体文件后调用接口 | verified |
| 审计 | 记录导出人、项目、实际起止日期、生成时间、行数和结果状态 | 数据库审计查询 | confirmed |

## 周报

| 需求 | 验收标准 | 验证方式 | 状态 |
| --- | --- | --- | --- |
| 唯一性 | 同一用户、项目、周只能有一份；重复新建打开已有记录或返回明确冲突 | API 唯一性测试 | confirmed |
| 填写保存 | 所有启用项目均可选；周区间为周一至周日；本周完成和下周计划必填；首次保存即生效，不出现提交/审核/驳回状态 | API + 桌面/移动端浏览器 | confirmed |
| 编辑权限 | 用户可编辑本人周报；管理员可编辑任意用户周报且不改变原作者；普通用户编辑他人记录返回 403 | 权限矩阵测试 | confirmed |
| 编辑审计 | 每次保存更新最后编辑人和时间并写入审计；管理员修改后页面显示最后编辑信息 | API/数据库检查 | confirmed |

## 用户资料

| 需求 | 验收标准 | 验证方式 | 状态 |
| --- | --- | --- | --- |
| 登录硬门禁 | 银行卡未填写时登录后直接进入个人资料页；直接输入其他业务路由仍被重定向；绕过前端调用其他业务 API 被拒绝；个人资料、修改密码和退出仍可用 | API + 路由守卫 + 浏览器登录流程 | confirmed |
| 资料补全 | 个人姓名和 16-19 位银行卡号均填写后解除门禁；页面明确说明报销及餐补发放使用该银行卡；银行卡不能被保存为空 | API + 浏览器表单 | confirmed |
| 发放前校验 | 姓名或银行卡缺失时不能确认差旅报销或餐补发放；完整资料可继续 | 服务端业务测试 | confirmed |
| 管理员查看复制 | 管理员用户页面直接显示完整卡号且无脱敏；卡号旁有复制图标按钮；点击后剪贴板内容与卡号一致并显示复制成功；普通用户无法读取他人资料 | API 权限测试 + 浏览器剪贴板测试 | confirmed |
| 敏感数据 | 完整卡号只出现在本人资料和管理员专用用户响应/页面，不出现在 JWT、报销导出、日志、异常响应或历史发放记录；查看和复制审计不保存卡号原文 | 响应/文件/日志扫描 | confirmed |

## 统一验收

- 新增写操作遵循现有事务与并发令牌模式，失败不得留下半条记录。
- 状态变化、联动驳回、金额确认、发放、导出、完整卡号查看/复制和周报编辑均有审计记录。
- 后端构建、自动化测试、前端生产构建通过，并完成普通用户/管理员权限矩阵测试。
