# 报销与餐补看板：业务边界

## 做什么

- 将现有“餐补详情”统一改称“餐补看板”。
- 为管理员新增独立“报销看板”，逐条展示当前版本费用明细。
- 报销看板支持费用类别、费用日期、项目和人员筛选。
- 餐补看板支持按项目/人员划分；报销看板支持按项目/人员/类别划分，并展示服务端全量分组汇总。
- 两个看板都能打开关联报销详情。

## 不做什么

- 不把历史版本费用明细或餐补作为当前看板独立行。
- 不在报销看板中包含餐补。
- 不新增编辑、审批、驳回或发放入口。
- 不修改金额、状态、发放、凭证、导出和数据库结构。
- 不修改“报销管理”现有划分方式。

## 角色与权限

| 角色 | 权限 |
| --- | --- |
| Administrator | 访问两个看板、筛选、切换划分方式、分页、查看报销详情 |
| Applicant | 不访问全量管理员看板，仍通过“我的报销”查看本人数据 |

## 数据归属

```text
ReimbursementClaim
  -> CurrentVersion
      -> ExpenseItems[]       报销看板，一行一个费用明细
      -> MealAllowance?       餐补看板，一行一个餐补
  -> Applicant
```

- 报销看板金额只取 `ExpenseItem.Amount`，不使用版本总金额，也不加餐补。
- 餐补看板金额继续取 `MealAllowance.TotalAmount`。
- 两个看板的项目和人员筛选都基于报销当前版本及申请人。

## 时间与空值边界

- 报销看板按单条费用的 `ExpenseDate` 做闭区间筛选。
- 餐补看板继续按行程区间与筛选区间相交。
- 草稿和已作废报销不进入报销看板列表、汇总或分组；其余纳入状态若存在空日期，未指定时间时可见，指定时间后不命中。
- 空金额显示“金额待填写/待核定”，服务端金额汇总按 0 处理并单独统计空金额数量。

## 分组边界

- “按项目”“按人员”和报销看板的“按类别”只改变分组卡片，不改变明细表格的行粒度。
- 分组卡片统计完整筛选结果，不受分页影响。
- 点击卡片设置对应项目或人员筛选；再次点击取消。
- 报销看板按项目、人员或费用类别显示费用明细数和已填写金额；餐补看板按项目或人员显示餐补数和已核定金额。

## 权限、审计和财务边界

- 后端接口继承 `Administrator` 授权，不依赖前端隐藏实现权限。
- 本轮全部接口只读，不产生新的业务审计记录。
- 汇总用于查询展示，不改变报销或餐补的财务确认、发放状态和导出口径。

## 需要一次性确认

- 餐补保留 `/admin/meal-allowances`，仅将可见名称改为“餐补看板”。
- 报销看板只展示当前版本中待审批、已批准和已驳回的费用明细；草稿、已作废和餐补不计入。
- 报销时间筛选使用 `ExpenseDate`。
- 报销看板额外支持按费用类别划分；餐补看板不增加类别维度。
- 两个看板保持只读，空金额按 0 汇总并单独计数。
