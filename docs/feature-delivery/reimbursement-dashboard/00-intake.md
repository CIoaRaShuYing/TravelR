# 报销与餐补看板：需求接收

## 用户原始目标

1. “餐补详情”改名为“餐补看板”。
2. 新增“报销看板”功能路由，按“费用明细”逐条列出，可按费用类别、时间、项目和人员筛选。
3. 将“报销管理”的“划分方式”加入餐补看板和报销看板。

## 推断出的业务目标

- 把“报销管理”的流程操作与“报销看板”的明细分析分开。
- 管理员可以从费用明细和餐补两个粒度查看、筛选和按项目/人员汇总当前有效数据。
- 两个看板采用一致的筛选、分组卡片、分页和详情追溯交互。

## 当前已知约束

- `ExpenseItem` 属于 `ClaimVersion`；报销修改会保留旧版本。
- `MealAllowance` 不是 `ExpenseItem`，不能在报销看板中重复列出或计入金额。
- 现有看板与管理员 API 均只向 `Administrator` 开放。
- 本轮不改变报销审批、发放、餐补审批、金额核定或附件规则。

## 推荐假设

- “费用类比”按“费用类别”理解。
- “餐补看板”仅修改页面标题、导航名称和相关文档名称，保留现有 `/admin/meal-allowances` URL 与 API，避免破坏书签和既有调用。
- 新页面使用 `/admin/reimbursement-dashboard`，后端资源接口使用 `/api/admin/expense-items`。
- 报销看板每行是一条当前报销版本的 `ExpenseItem`，不包含餐补。
- 时间筛选使用 `ExpenseItem.ExpenseDate`，开始和结束日期均包含；指定日期范围时，无费用日期的纳入明细不命中。
- 报销看板仅纳入待审批、已批准和已驳回的当前版本费用明细；草稿和已作废不进入列表、汇总或分组。
- 餐补看板的“划分方式”提供“按项目/按人员”；报销看板提供“按项目/按人员/按类别”。分组数据基于完整筛选集而非当前页，点击分组卡片设置或取消对应筛选。

## 未经确认不得修改的内容

- 前后端生产代码、路由、导航和 API 合同。
- 报销/餐补状态机、数据库结构和金额规则。

## 确认结果

- 2026-09-08：用户确认草稿和已作废不纳入报销看板，并要求报销看板增加按类别划分。
- 2026-09-08：用户回复“开始实施”，需求与验收确认通过。

## 本轮范围

- 先完成调研、业务边界、需求和验收标准并请求一次确认。
- 确认后实现两个看板的命名和分组扩展，以及新的报销看板纵切片。
