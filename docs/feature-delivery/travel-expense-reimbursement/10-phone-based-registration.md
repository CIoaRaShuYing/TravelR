# 手机号注册与登录

## 业务边界

- 注册不采集邮箱；注册表单仅包含姓名、11 位中国大陆手机号和密码。
- 手机号是唯一账号标识，登录也改为手机号和密码。
- 邮箱不再参与注册去重、待审核申请去重或 JWT 用户信息展示。
- 首位管理员自助注册规则与三态注册规则继续适用，均以手机号识别用户。
- 不包含短信验证码、手机号真实性校验或已有邮箱账号自动迁移。

## 需求与验收

- REQ-PHONE-001：注册接口和页面拒绝非 11 位中国大陆手机号，接受姓名、手机号、密码。
- REQ-PHONE-002：手机号在正式账户和待审核注册申请中均不可重复。
- REQ-PHONE-003：登录接口和页面使用手机号与密码；成功响应不再要求邮箱字段。
- REQ-PHONE-004：空库首位手机号注册用户仍拥有管理员、审核人、申请人角色。
- REQ-PHONE-005：数据库使用唯一手机号索引；现有邮箱账号不自动转换为手机号账号。

## 实施方案

1. 将请求契约、注册申请实体和索引从 `Email` 改为 `PhoneNumber`，并对 `AppUser.PhoneNumber` 配置唯一索引。
2. 注册和登录统一规范化手机号；新用户以手机号作为 `UserName` 与 `PhoneNumber`。
3. 更新前端字段、标签、输入类型和错误提示。
4. 新增 EF Core 迁移，保留 Identity 原有邮箱列以兼容框架，但业务不再使用它。

## 待确认

- 默认按“手机号同时作为登录账号”实施；不保留邮箱登录兼容。
