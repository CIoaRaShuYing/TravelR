# 差旅报销 Web：需求草案

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| REQ-001 | Must | 管理员可切换开放注册、审核注册、不开放注册；模式切换即时作用于新访客。 |
| REQ-002 | Must | 开放注册模式下，访客完成校验后立即获得可登录账号。 |
| REQ-003 | Must | 审核注册模式下，访客提交申请后不可登录；管理员批准后才可登录，拒绝需保留理由。 |
| REQ-004 | Must | 已存在管理员时，不开放注册模式下注册入口和注册接口均不可创建用户；管理员仍可后台创建用户。系统尚无管理员时，首位管理员自助注册不受该模式阻断。 |
| REQ-005 | Must | 申请人可创建两类报销单：差旅行程报销、单据报销；两类均为必填报销说明。 |
| REQ-006 | Must | 差旅行程报销能录入行程基础信息及出发交通、回程交通、可选住宿凭证；每类支持多张凭证和附件；允许出发日期与返程日期相同。 |
| REQ-007 | Must | 差旅行程仅在出发交通与回程交通凭证均存在、说明已填写时允许提交；住宿在任何行程中均不是提交前置条件。当天往返可不录入住宿，草稿可不完整。 |
| REQ-008 | Must | 单据报销可录入办公用品、聚餐等任意费用类别及附件，不受行程票据限制。 |
| REQ-009 | Must | 已提交报销单进入审核流，审核人可批准或驳回；驳回须填写原因，申请人可修改后重提。 |
| REQ-010 | Must | 系统保留用户注册、报销状态流转、审核意见及附件操作的审计信息。 |
| REQ-011 | Should | 管理员可查看和筛选全部注册申请、报销单及审核状态。 |
| REQ-012 | Should | 支持图片和 PDF 格式凭证，限制文件类型、大小、私有访问和恶意文件扫描接入点。 |
| REQ-013 | Optional | 财务复核、付款状态、导出 Excel/PDF、消息通知、组织/部门审批规则。 |
| REQ-014 | Out of scope | OCR、发票验真、自动查重、银行付款、外部财务系统实时同步。 |
| REQ-015 | Must | 系统无管理员时，公开注册设置须声明首位管理员注册可用，注册页以醒目提示说明首位用户将获得管理员、审核人和申请人权限；立即注册成功后自动切回登录界面并带入手机号。待审核申请不视为注册成功。 |

## 方案选择约束

- 直接使用开源项目只有在接受其数据模型、UI、角色体系和部署栈时才成立。
- 如果只需要报销而非完整 ERP/HR，系统应避免引入薪酬、采购、总账等不在范围的模块。
- 若未来形成对外交付的软件产品，应优先规避 GPL/AGPL 衍生代码的许可证约束，或进行专门法务评估。
