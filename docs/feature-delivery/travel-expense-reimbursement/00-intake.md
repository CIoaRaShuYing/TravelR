# 差旅报销 Web：需求接收

## 用户原始目标

建设一个差旅报销 Web 网页：用户可注册账户；管理员可切换开放注册、管理员审核注册、不开放注册三种模式。注册成功的用户可提交两类报销：

- 差旅行程报销：一次完整行程，包含出发交通发票、回程交通发票、期间住宿发票。
- 单据报销：办公用品、聚餐等不属于行程的独立报销。

两类报销均必须填写报销说明。

## 本轮范围

- 调研可用开源项目及许可证、维护和功能匹配度。
- 建立业务边界、需求草案和验收标准。
- 给出独立开发、参照开发、二次开发、直接使用四种路径的建议。

## 已知约束

- 当前 `D:\Code\chuchai` 为空目录，未提供既有技术栈或现有系统。
- 本轮不编写生产代码、不创建可运行系统。
- 需把“行程”作为独立业务对象，不能仅把各票据散落为普通费用条目。

## 待确认事项

- 是否需要审批流、财务复核、付款登记及驳回后修改重提。
- 发票是否需 OCR、验真、查重或税务合规对接。
- 是否需要对接现有组织、单点登录、财务/ERP、企业微信/钉钉。
- 部署形态、用户规模、数据合规要求及是否允许 GPL/AGPL 许可证。

## 暂定假设

- 首期仅支持网页端、账号密码登录、图片/PDF 附件和人工审核。
- 报销金额、币种、费用日期、费用类别和附件均应留存审计记录。
- 用户已确认：差旅行程提交时仅强制要求去程交通与回程交通；住宿为可选项，以支持当天往返。
