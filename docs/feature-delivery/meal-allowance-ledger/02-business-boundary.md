# 餐补详情台账：业务边界

## 做什么

- 为管理员增加独立餐补台账路由和导航入口。
- 展示每个报销当前版本的餐补信息。
- 支持行程日期、项目、申请人筛选和分页。
- 支持打开现有报销详情抽屉查看完整版本、审核和发放记录。

## 不做什么

- 不展示旧报销版本餐补作为独立台账行。
- 不新增、编辑或删除餐补；餐补仍由差旅报销自动创建。
- 不复制批准、驳回、确认发放等写操作。
- 不修改餐补金额、状态机、发放规则、导出或数据库结构。

## 角色与权限

| 角色 | 权限 |
| --- | --- |
| Administrator | 访问餐补详情台账、筛选、分页、查看关联报销详情 |
| Applicant | 不访问管理员餐补台账；仍通过“我的报销”查看自己的餐补 |

## 核心业务对象与数据归属

```text
ReimbursementClaim
  -> CurrentVersion
      -> Project
      -> MealAllowance
  -> Applicant
```

- 台账行归属于报销当前版本，不创建新的餐补副本。
- 项目使用当前版本的项目快照语义；申请人来自报销主记录。
- 金额待核定时 `DailyAmount`、`TotalAmount` 为 `null`，页面展示“金额待核定”，金额汇总按 0。

## 时间筛选边界

- 推荐按行程日期区间筛选。
- 采用区间相交规则：餐补返程日期不早于筛选开始日，且餐补出发日期不晚于筛选结束日。
- 任一边界为空时只应用另一侧；餐补行程日期不完整时不命中已指定的日期过滤。

## 状态与审计边界

- 页面读取全部当前餐补状态，不隐含“只看待处理”。
- 审批和发放仍在“报销管理”完成，保证现有并发令牌和审计入口不分叉。
- 详情按钮复用现有报销详情抽屉。

## 待确认边界

- 行程日期筛选。
- 只列当前版本但包含全部状态。
- 新页面只读，不复制审批和发放动作。
