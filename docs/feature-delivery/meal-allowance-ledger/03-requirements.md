# 餐补看板：需求说明

## REQ-001

- 优先级：Must
- 业务目的：提供独立、可直达的管理员餐补台账。
- 影响角色：Administrator。
- 输入：访问 `/admin/meal-allowances` 或点击“餐补看板”导航。
- 输出：独立餐补列表页面。
- 涉及模块：Vue Router、AppShell、管理员权限守卫、新页面。
- 默认假设：仅管理员可访问。
- 依赖事项：现有登录、角色和资料完整性守卫。
- 不做事项：不向 Applicant 开放管理员全量数据。

## REQ-002

- 优先级：Must
- 业务目的：集中查看不重复的当前餐补数据。
- 影响角色：Administrator。
- 输入：所有报销主记录。
- 输出：只返回存在餐补的当前版本，每行包括申请人、项目、报销号/版本、行程起止、天数、每日金额、餐补总额、餐补状态、发放状态和更新时间。
- 涉及模块：管理员 API、前端 API 类型、餐补看板页面。
- 默认假设：包含全部当前餐补状态；金额未核定时显示待核定并按 0 汇总。
- 依赖事项：`CurrentVersion.MealAllowance`。
- 不做事项：不把旧版本餐补计为独立行。

## REQ-003

- 优先级：Must
- 业务目的：按业务维度快速定位餐补。
- 影响角色：Administrator。
- 输入：行程日期范围、项目、申请人。
- 输出：三个筛选条件可单独或组合生效，结果和汇总基于完整筛选集而非当前分页。
- 涉及模块：管理员餐补 API、新页面筛选区。
- 默认假设：日期按餐补行程区间相交判断。
- 依赖事项：现有项目列表和申请人目录 API。
- 不做事项：本轮不增加审核状态、发放状态搜索条件。

## REQ-004

- 优先级：Must
- 业务目的：从餐补台账追溯完整报销上下文。
- 影响角色：Administrator。
- 输入：点击某条餐补的“查看详情”。
- 输出：打开现有 `ClaimDetailDrawer`，展示当前版本及历史审计信息。
- 涉及模块：新页面、`ClaimDetailDrawer.vue`。
- 默认假设：不新建第二套详情组件。
- 依赖事项：现有 `/claims/{id}` 和版本详情 API。
- 不做事项：不在新页面直接批准、驳回或发放。

## REQ-005

- 优先级：Should
- 业务目的：让管理员快速掌握筛选范围的餐补规模。
- 影响角色：Administrator。
- 输入：当前筛选条件。
- 输出：显示餐补笔数、已核定金额、待核定笔数；分页支持大数据量。
- 涉及模块：管理员餐补 API、页面汇总带。
- 默认假设：待核定金额按 0 计入金额汇总。
- 依赖事项：服务端聚合查询。
- 不做事项：不新增图表或导出。
