# 项目会议记录：需求接收

## 用户原始目标

新增用户会议记录填写能力：用户可以选择项目填写和修改会议记录；会议记录所有用户都能看到并修改；日期由用户选择；支持按项目导出；导出结果按一条会议记录一张表格组织；内容和样式参考 `会议记录.xlsx`。

## 2026-09-03 确认结果

- 同一项目每周可有多份会议记录，同一天也不设置唯一限制。
- 所有已登录且个人资料完整的用户都可查看、创建和编辑全部会议记录。
- 创建人不随编辑变化；保留最后编辑人、创建时间、更新时间、审计和并发保护。
- 参会人员、需求内容和工作重点均支持动态增删行。
- 需求内容和工作重点字段统一为：内容、状态、截止日期、负责人；状态采用自由文本。
- 会议日期不沿用周报的周一限制，用户可选择任意日期；暂不采集具体时分。
- 导出时选择一个项目，一份 Excel 包含该项目全部会议记录，每条记录一个工作表。
- 只有管理员可以删除某次会议记录。
- 系统每周对会议记录执行一次全量备份，并永久保存在服务器。

## 推断出的业务目标

在现有“差旅账”中新增独立的“项目会议记录”模块，为项目团队持续维护共享会议纪要，提供管理员治理能力、模板化 Excel 归档和服务器端周期性全量备份。

## 实施假设

- 删除采用软删除：普通查询和项目导出不再显示，数据库、审计和全量备份仍保留删除记录及删除人、删除时间。
- 每周日北京时间 02:00 生成一次全量快照；服务停机错过执行时间后，恢复运行时补做当周快照。
- 备份使用不可覆盖的 ZIP 文件，包含 JSON 数据和 manifest/checksum，覆盖全部会议记录、参会人员、会议事项及删除元数据。
- 备份写入独立服务器目录；Docker 部署使用独立持久卷，应用不提供自动清理能力。
- “永久存储”表示应用层不设置保留期限；服务器磁盘、Docker 卷损坏或被人工删除不属于应用可保证范围，仍需纳入服务器级备份。
- 不提供审批、提交、锁定、附件、通知或正文版本恢复。
