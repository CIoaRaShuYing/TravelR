# 报销归档批次：需求接收

## 用户目标

管理员每月完成统一报销审核和发放后，按父报销提交日期范围创建一个自定义名称的归档批次。批次应固定保存本次报销成员；餐补随父报销归入同一批次。归档后，报销管理、报销看板和餐补看板均可按归档批次筛选和划分，并能按批次重新导出完整 ZIP。

## 已确认约束

- 归档是数据库中的逻辑目录，不移动或复制凭证文件。
- 日期口径为父报销 `SubmittedAt`，按中国时区自然日含首尾。
- 批次覆盖全部项目，不受页面分页影响。
- 仅已结案记录可归档；任一报销或餐补仍在审批、发放流程中时整批失败。
- 餐补不保存独立归档关系，始终继承父报销批次。
- “已归档”是独立维度，不覆盖报销审批状态或发放状态。
- 批次成员创建后不可增删；名称可修改并记录审计；首版不删除批次、不移出单条报销。
- 归档 ZIP 按批次固化成员生成，不按日期重新计算。

## 本轮范围

交付领域模型、迁移、归档资格与事务服务、管理接口、精确批次 ZIP、三个管理查询面的筛选/分组、前端交互、自动化测试和验证记录。
