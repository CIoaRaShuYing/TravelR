# 用户中心与申请人筛选修复：需求说明

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| REQ-UC-001 | Must | 管理员可访问独立“用户中心”页面，查看正式用户的姓名、手机号、角色和启用状态；响应不得包含密码或密码哈希。 |
| REQ-UC-002 | Must | 用户中心支持按启用状态和姓名/手机号关键字筛选，并使用服务端分页。 |
| REQ-UC-003 | Must | 管理员可启用或停用正式用户；操作需服务端校验管理员权限、记录审计，并保留用户及历史报销数据。 |
| REQ-UC-004 | Must | 普通申请人不能调用用户中心列表或启停接口；未授权请求返回现有约定的 401/403。 |
| REQ-AP-001 | Must | 报销管理的申请人下拉改为查询所有正式、启用且拥有 `Applicant` 角色的用户。 |
| REQ-AP-002 | Must | 开放注册后直接成为 `Applicant` 的用户，以及管理员批准后的 `Applicant` 用户，即使尚无报销，也必须出现在申请人下拉。 |
| REQ-AP-003 | Must | 申请人目录支持姓名/手机号关键字和服务端分页；下拉展示姓名与手机号，选中后仍按用户 ID 筛选报销。 |
| REQ-AP-004 | Must | 申请人目录不包含待审批注册申请、无 `Applicant` 角色用户或已停用用户。 |
| REQ-AP-005 | Should | 报销管理按申请人分组的汇总仍只展示当前筛选条件下有报销的分组；目录选项与汇总分组解耦。 |

## 默认假设

- 用户中心仅做正式用户查询和启停，不扩展新增账号、改密、改角色。
- 管理员自身也可作为申请人被列出，因为当前首位管理员同时拥有 `Applicant` 角色。
