# 用户中心与申请人筛选修复：业务边界

## 业务目标

让管理员能看见和控制正式用户账号，让报销管理能按全部正式申请人检索，而不受“是否已经提交过报销”影响。

## 角色与职责

| 角色 | 允许事项 |
| --- | --- |
| `Administrator` | 查看正式用户目录、按关键字/状态筛选、启用或停用账号、使用全部申请人筛选、继续执行既有注册审批和报销管理 |
| `Applicant` | 继续使用自己的报销功能；不能读取用户目录、不能启停账号 |

## 核心对象

- 正式用户：`AppUser`，必须已经拥有 `Applicant` 或 `Administrator` 角色。
- 申请人目录项：正式、启用且拥有 `Applicant` 角色的用户，包含 `id`、姓名、手机号、启用状态（如需要）及角色摘要。
- 用户管理行：正式用户的基础展示信息、角色、启用状态、创建时间和最近登录不可用信息；本轮不新增登录审计字段。

## 状态与流向

```text
注册开放 -> AppUser(Applicant, IsActive=true)
注册审批 -> RegistrationRequest.Pending
管理员批准 -> AppUser(Applicant, IsActive=true)
用户中心停用 -> AppUser(IsActive=false) -> JWT 后续请求失效
用户中心启用 -> AppUser(IsActive=true) -> 可重新登录
```

待审批注册申请仍归“注册审批”页面，不进入正式用户中心和申请人目录。

## 数据归属

- 用户和角色由 ASP.NET Identity 持有。
- 账号启停由管理员通过后端 API 修改 `AppUser.IsActive`，并写入现有 `AuditLog`。
- 申请人筛选数据由后端按角色和启用状态查询 Identity 数据，不从报销聚合反推。

## 明确不做

- 不允许物理删除用户。
- 不在本轮新增用户、重置密码、修改手机号、修改角色、批量导入或项目成员关系。
- 不把待审批 `RegistrationRequest` 伪装成正式申请人。
- 不改变普通申请人只能访问本人报销的权限边界。
