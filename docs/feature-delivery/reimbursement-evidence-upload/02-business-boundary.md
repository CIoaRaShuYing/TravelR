# 报销凭证分类与拖拽上传：业务边界

## 做什么

- 每条费用提供“发票”和“支付记录”两个独立上传区域。
- 两个区域均支持点击选取和拖拽上传，可各自包含多份文件。
- 提交校验采用 OR 规则：每条费用的发票或支付记录合计至少一份有效附件即可。
- 保存附件用途，并在报销编辑和详情审核中清晰展示分类。

## 谁负责

| 角色/组件 | 职责 |
| --- | --- |
| 申请人 | 选择正确上传区域、补充或移除当前版本中的凭证 |
| 前端 | 提供两个拖拽区、做即时最低校验、展示上传状态和分类 |
| API | 校验文件安全与归属、持久化用途、在提交时执行不可绕过的最低校验 |
| 管理员 | 根据附件内容与业务规则决定批准或驳回，不由系统自动判真 |
| 私有文件存储 | 保存文件实体，不负责发票识别、支付核验或业务分类推断 |

## 数据归属与流向

```text
发票拖拽区 / 支付记录拖拽区
        -> 鉴权暂存上传（文件 + 用途）
        -> AttachmentAsset（私有文件元数据 + 用途）
        -> ExpenseItemAttachment
        -> ClaimVersion 费用明细
        -> 申请人/管理员详情按用途展示
```

## 权限与审计边界

- 不改变现有附件权限：所有者和管理员可访问，附件不公开暴露。
- 不改变附件暂存、绑定、过期清理、哈希和类型校验。
- 分类随附件元数据保存；不增加 OCR、发票验真、支付平台核验或自动审批。

## 状态与审批边界

- 报销提交、批准、驳回、作废、发放状态机保持不变。
- “至少一类凭证”只是提交门槛，不代表凭证合规，也不意味着管理员必须批准。
- 已保存的旧版本保持只读；其历史附件按用户确认的业务口径统一显示为“发票”。

## 明确不做

- 不判断发票真假、金额一致性、抬头、税号或支付人与申请人的一致性。
- 不接入 OCR、税务、银行或支付平台。
- 不改变月度导出的 Excel 内容和现有 ZIP 目录结构，所有附件继续位于 `报销凭证/`。
- 不改变单文件格式和 10MB 大小限制。

## 已确认的关键边界

- 最低校验按每条费用执行。
- 历史附件全部归为发票并继续计入“至少一份凭证”。
- 本轮不对 ZIP 导出按凭证类别拆目录。
