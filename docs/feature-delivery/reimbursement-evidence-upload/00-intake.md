# 报销凭证分类与拖拽上传：需求接收

## 用户原始目标

1. 将费用明细中的凭证上传拆成“发票上传”和“支付记录上传”两个按钮或区域。
2. 前端提交时，发票或支付记录任一类存在即可通过必填校验；凭证是否足以通过报销审核由管理员判断。
3. 所有报销文件上传位置支持拖拽上传。

## 推断出的业务目标

- 申请人可以按凭证用途分类上传，减少管理员人工辨认成本。
- 系统只检查每项费用至少提供一份可用凭证，不替管理员判断发票或支付记录的业务有效性。
- 分类在保存、重新打开、版本查看和管理员审核时不能丢失。

## 当前已知约束

- 现有单个附件仍限制为 JPG、PNG 或 PDF，最大 10MB。
- 报销和附件仍遵循私有存储、鉴权访问、不可变版本与管理员审核边界。
- 本轮不改变报销审批状态机、付款确认、金额计算或附件文件存储方式。
- “上传文件的位置”按当前代码事实限定为报销编辑器中唯一的附件上传入口；当前前端没有其他文件上传控件。

## 暂定假设

- “有其一都能过”按每一条费用明细分别判断，而不是整张报销单只需任意一个附件。
- 两类区域都允许添加多份文件，并支持点击选择与拖拽。
- 分类应持久化并在申请人编辑和管理员详情中展示；仅做视觉拆分但保存后丢失分类不视为完成。
- 用户已确认历史附件直接归类为“发票”，迁移后不设置“历史未分类凭证”。

## 已确认事项

- 最低校验按每条费用执行，发票与支付记录任一类存在即可。
- 历史附件全部定义为“发票”。
- 月度 ZIP 不按类别拆目录，继续全部放在 `报销凭证/` 下。
- 2026-09-08 用户完成需求与验收确认，允许进入技术设计和实施。

## 不修改的内容

- 现有审批、发放和导出业务规则。

## 本轮范围
