# 报销凭证分类与拖拽上传：需求说明

## REQ-001

- 优先级：Must
- 业务目的：让申请人按凭证用途上传。
- 影响角色：申请人、管理员。
- 输入：每条费用的发票文件和支付记录文件。
- 输出：发票与支付记录两个独立上传区域及分类附件列表。
- 涉及模块：`ClaimEditorDialog.vue`、附件上传 API、附件元数据。
- 默认假设：两区均允许多文件；支持 JPG、PNG、PDF，单个不超过 10MB。
- 依赖事项：附件用途必须持久化。
- 不做事项：不自动识别文件类型或内容。

## REQ-002

- 优先级：Must
- 业务目的：不因只具备一种凭证而阻止报销提交。
- 影响角色：申请人。
- 输入：每条费用已绑定的有效附件。
- 输出：发票、支付记录任一类至少一份即可通过前后端最低校验；两类都没有时阻止提交。
- 涉及模块：前端提交校验、`ClaimSubmissionValidator`。
- 默认假设：规则逐条费用执行；历史附件迁移为发票并继续计入，避免旧数据无法继续流转。
- 依赖事项：附件 `ScanStatus` 仍必须为 `Accepted`。
- 不做事项：不把最低校验结果等同于审批通过。

## REQ-003

- 优先级：Must
- 业务目的：提高批量添加凭证的操作效率。
- 影响角色：申请人。
- 输入：拖入发票区或支付记录区的一个或多个文件。
- 输出：文件上传至对应分类，并显示上传状态、成功结果或明确错误。
- 涉及模块：`ClaimEditorDialog.vue`、Element Plus `el-upload`。
- 默认假设：点击选择仍保留；拖入哪个区域即采用哪个用途。
- 依赖事项：现有单文件上传接口和校验。
- 不做事项：不新增第三方上传库。

## REQ-004

- 优先级：Must
- 业务目的：让管理员依据明确分类审核，同时保留版本审计事实。
- 影响角色：申请人、管理员。
- 输入：已保存的分类附件与迁移前历史附件。
- 输出：编辑器重新打开和详情抽屉均按“发票”“支付记录”展示；迁移前历史附件显示为发票。
- 涉及模块：详情 API 投影、`frontend/src/api.ts`、`ClaimEditorDialog.vue`、`ClaimDetailDrawer.vue`。
- 默认假设：按用户确认口径将历史附件统一定义为发票；旧版本业务内容不被重写。
- 依赖事项：兼容数据库迁移。
- 不做事项：不逐份人工判断历史附件类别。

## REQ-005

- 优先级：Should
- 业务目的：保持既有附件和导出能力稳定。
- 影响角色：申请人、管理员、运维。
- 输入：分类附件。
- 输出：预览、下载、私有鉴权、版本绑定、过期暂存清理和月度 ZIP 导出继续工作。
- 涉及模块：现有附件服务与 `MonthlyClaimExportService`。
- 默认假设：ZIP 不按类别拆分目录，全部保留在 `报销凭证/`。
- 依赖事项：不得改变对象键和文件实体。
- 不做事项：不修改导出文件命名规则。
